# A1V1: 25 gambar per model — 14 Oktober 2026

25 gambar yang sama untuk setiap model: 13 Nutrition5k + 12 LeFood. Pemilihan adalah prefix dari manifest 50+50 yang telah dikunci, tanpa memilih ulang berdasarkan hasil. Jumlah panggilan target 50.
Varian A1V1-schema-v2: prompt diperjelas dan response_format=json_schema dengan strict=true serta additionalProperties=false pada setiap object. Kedua model mendapat prompt/schema identik; tidak boleh menambahkan field di luar diameter, volume, berat, komponen, nutrisi dan limitations.
Kontrol: endpoint Singapore yang sama dengan B0; temperature=0; enable_thinking=false; max_tokens=1024; tidak ada model fallback. Inferensi dilakukan satu per satu di API Alibaba dengan client CPU-only. Retry hanya untuk network/rate-limit/server error, maksimal dua; tidak ada retry untuk jawaban yang gagal validasi.
Run ini memakai prompt/format baru. Skor 5-gambar sebelumnya tidak dicampur dengan benchmark ini. Sebagian sampel sudah pernah diperiksa; benchmark belum menjadi validasi independen.

## Reproduksi dan cakupan

```sh
CUDA_VISIBLE_DEVICES='' python3 experiments/model-evaluation/scripts/run_a1v1_benchmark25.py
# Melanjutkan hanya sampel yang belum diproses:
CUDA_VISIBLE_DEVICES='' python3 experiments/model-evaluation/scripts/run_a1v1_benchmark25.py --resume
# Laporan saja, tanpa inferensi baru:
python3 experiments/model-evaluation/scripts/run_a1v1_benchmark25.py --report-only
```

Artefak: study.json mengunci pemilihan/checksum, tiap model memiliki run metadata, requests, raw responses, details, validation-errors, predictions dan reports. comparison.json menyimpan coverage, pasangan sama, label dan hasil audit kontrol.
Schema/format disiapkan berdasarkan [dokumentasi resmi Alibaba](https://www.alibabacloud.com/help/en/model-studio/qwen-structured-output). JSON Schema membatasi struktur; kebenaran nama makanan, massa dan nutrisi tetap harus dievaluasi. Parser tetap memeriksa nilai finite/nonnegative, nonfood null, key order geometry dan limitations.
A1V1 tetap menggunakan tebakan nutrisi langsung dari VLM. Run ini tidak memakai katalog A6, model segmentasi/depth, atau GPU lokal. Tidak ada perubahan default produksi FastAPI. Kode/prompt/laporan berada di branch feat/t32-real-ai-service dan belum di-commit.

## Hasil dan handoff

Max lebih rendah untuk MAE massa (37,667 vs 57,625 g), energi (112,528 vs 141,140 kcal) dan karbohidrat (7,723 vs 13,576 g). Flash lebih rendah untuk protein (8,093 vs 8,546 g) dan lemak (8,961 vs 9,591 g). Dengan normalisasi/bobot yang sama, overall Max 38,321% vs Flash 47,203%. MAE massa Max turun 34,6% dan energi 20,3%, sementara latency rata-rata naik 37,6% (5,585 vs 4,059 detik). Token per gambar 1.263 vs 1.234 tidak menyatakan kesamaan biaya antar-model.

Kedua model memproses seluruh 25 gambar dengan validasi 25/25, coverage massa 24/24 dan energi/macro 12/12. Piring kosong dikenali sebagai nonfood dengan angka null. Ada 50 panggilan aktual, masing-masing satu attempt, tanpa fallback, ekstra field atau truncation. Bubur masih salah dikenali sebagai Nasi pada kedua model, sehingga perbaikan format belum memperbaiki semua kesalahan semantik.

Verifikasi: 62 tes offline eksperimen lolos, termasuk pengiriman strict schema ke dua model tanpa GT leakage, nonfood null, dan penolakan field tambahan tanpa repair. Syntax/diff checks lolos. Audit terpisah membaca semua 50 raw response, memverifikasi prompt/schema/parameter/checksum/model yang sama sesuai plan, dan menghitung ulang lima MAE langsung dari raw values dan GT; semua cocok dengan comparison.json. Audit tersimpan di `results/a1v1-strict-25-2026-10-14/control-audit.json`.

Cakupan perubahan: runner baru, prompt/schema A1V1 v2, tiga tes dan tautan laporan. Kode dan dokumentasi masih uncommitted pada branch yang diminta, bersama pekerjaan ablasi sebelumnya. Belum diverifikasi: akurasi pada set independen, latency end-to-end di HP/VPS, load/concurrency produksi, dan deployment ke service nyata. Model API tetap menjadi sumber estimasi; penerimaan JSON bukan bukti benar secara nutrisi.
